# 校园地图完整接入说明

交付日期：2026-10-16。建议按“本地检查 → 手机浏览器 → HTTPS 部署 → 现有小程序接入 → 微信真机验收”的顺序进行。此说明不执行服务器变更或小程序上传。

## 1. 接入结构与边界

本方案使用现有 3D 网页，通过组织主体小程序的原生 `web-view` 页面承载；3D 不需要重新改写成微信原生 Canvas。WebGL2 不可用或上下文丢失时自动切换完整 SVG 2D。

```text
原生首页入口 → pages/campus-map/index → HTTPS /campus-map/?embed=wechat
                                           ├─ Three.js 3D + 按距离分级
                                           └─ SVG 2D 降级／主动切换
```

网页独立，不接入原站账号、资料库、定位服务或课程接口。没有路线规划和 GPS 导航，不要将视觉模型当作测绘结果。业务域名是否可配置及主体资格，以组织小程序实际控制台和微信官方最新要求为准。

## 2. 解压与环境

解压到独立目录，例如 `D:\CampusMapDelivery`，不要直接解压覆盖原项目。

```powershell
cd D:\CampusMapDelivery
node --version
node verify-delivery.mjs
cd .\campus-map
npm ci
npm run check
```

建议 Node.js 22.12+ 的 22.x 版本；本机交付构建使用 Node.js 26.5.1 / npm 11.17.0。Vite 7 需要符合其 Node 版本要求，不要使用旧 Node 18。锁文件已提供，使用 `npm ci` 重现依赖，不要为预览执行 `npm update` 或 `npm audit fix --force`。

包内的默认 `npm run check` 是独立地图检查：构建、数据、全部几何、2D、安全深链接、手势／LOD、建筑保护、标签和模糊搜索，不依赖原网站旁边的 `miniprogram/`。为此只将交付副本的检查命令加上 `--web-only` 参数；应用源码、模型和锁文件没有改写。根目录校验器另行验证微信示例的固定来源、分享、错误和重试逻辑。

浏览器自动化脚本需要单独启动本机 Chrome 调试端口 9229 和 4180 预览；它们不属于安装后直接运行的普通检查，相关脚本中的截图输出目录来自原开发环境。不要直接运行它们并误以为普通 check 依赖那些绝对路径。开发日志及历史文档中的原目录、备份路径仅作历史记录，不是运行前置条件。

## 3. 本地与手机浏览器预览

### 3.1 电脑

```powershell
cd D:\CampusMapDelivery\campus-map
npm run preview -- --port 4180
```

打开 `http://127.0.0.1:4180/campus-map/`，显示电脑版。模拟手机界面用 `http://127.0.0.1:4180/campus-map/?embed=wechat`。不能直接双击 index.html／使用 file://。

修改代码时可用 `npm run dev -- --port 4178`；修改后重新 `npm run build`，再 preview 检查生产版本。端口被占用时关闭自己此前的服务或换端口，始终使用终端实际输出的地址。

### 3.2 手机

```powershell
npm run preview -- --host 0.0.0.0 --port 4180
```

电脑和手机接同一可信 Wi-Fi；用手机浏览器打开终端 Network 地址并带上 `?embed=wechat`。例如电脑局域网 IP 是 `192.168.1.20`，则打开 `http://192.168.1.20:4180/campus-map/?embed=wechat`。这里只是举例，不是已检测到的 IP。

访问失败依次检查服务仍在运行、路径和端口、两端网络是否相同、访客 Wi-Fi 是否隔离、私人网络防火墙是否允许该端口。不要关闭整个防火墙。此 HTTP 局域网地址不等于可发布的微信业务域名，不保证能在正式小程序 web-view 中打开。测试完 Ctrl+C 停止本地服务。

### 3.3 常用链接

| 参数 | 效果 |
| --- | --- |
| `?embed=wechat` | 全屏手机版布局 |
| `?embed=wechat&mode=2d` | 强制 2D |
| `?embed=wechat&buildingId=osm-building-616829077` | 中心图书馆 |
| `?embed=wechat&buildingId=reference-monument-zhou-enlai` | 周总理雕像 |
| `?embed=wechat&buildingId=place-cainiao` | 菜鸟驿站参考图估位标签 |
| `?detail=full` | 完整精细模型，适合电脑对照，不建议所有手机默认开启 |
| `?debug=1` | 开发用渲染统计 |

`buildingId` 是兼容保留的参数名，既可指建筑 ID，也可指地点目录 ID，不是任意网页地址。

## 4. HTTPS 静态部署

### 4.1 要上传什么

无需修改的当前版本：上传 `web-dist/` **里面的全部内容**。修改代码后：运行 `npm run check`，上传新生成的 `campus-map/dist/` 内容。

必须同时上传 index.html、assets/、credits.html、nankai-emblem-source.png 及其他构建输出。不要上传 src、data、reference、node_modules、微信示例或整个交付包到公共目录。不要覆盖原网站 dist。

默认网页地址结构为 `https://你的域名/campus-map/`，`vite.config.ts` 的 base 是 `/campus-map/`。如果改为其他路径，需要修改 base 后重新构建，同时修改微信示例配置的路径以及服务器 location；只改文件夹名字不够。

### 4.2 Nginx 示例

`deployment/campus-map-location.conf` 是放在**现有 HTTPS server 块内部**的静态片段，不是完整站点配置。管理员先备份并核对现有域名／证书配置，再按说明使用独立目录：

```text
/var/www/nkulawer-campus-map/releases/20261016/  本次 web-dist 内容
/var/www/nkulawer-campus-map/current/            当前发布目录（可为指向某次 release 的链接）
/var/www/nkulawer-campus-map/shared-assets/      历次哈希资源的累计保存目录
```

把此次 assets 内的文件复制进 shared-assets，保留旧哈希文件；index 和其他文件由 current 提供。不要在 shared-assets 上使用删除同步，否则旧页面可能加载失败。HTML／来源页不长缓存，带哈希资源可长缓存。

配置审核完成后由管理员先运行 `nginx -t`，成功才 reload。包内没有自动安装 Nginx、改防火墙、覆盖证书或发布网页的脚本。静态托管也可以使用，但必须支持 HTTPS、正确 `/campus-map/` 路径和缓存策略。Vite preview 只用于预览，不当生产服务器使用。[Vite 官方说明](https://vite.dev/guide/static-deploy.html)

### 4.3 部署后先验收网页

1. 浏览器打开 `/campus-map/`、`/campus-map/?embed=wechat` 和 `/campus-map/credits.html`。
2. 检查 index 引用的 JS／CSS 返回 200 且为正确类型，不能返回主站首页 HTML；校徽资源返回 200。
3. 图书馆、雕像、精细建筑、浅草绿地和图钉均出现；手机端搜索“公教A”“二食”“图书管”能定位。
4. 测试主界面的“全校视图”、图层顶部“关闭 ×”和空白关闭。
5. 测试主动 2D、3D、横竖屏和后台恢复。确认页面底部保留数据来源与待核验提醒。

## 5. 接入微信小程序

### 5.1 账号／域名准备

需要组织小程序管理员和服务器管理员协同。先确认该账号可以使用 web-view 并配置相应**业务域名**，按控制台要求完成 HTTPS、域名验证文件等步骤；“服务器 request 合法域名”不能替代网页 web-view 的业务域名设置。资格、备案及最新限制应由管理员核对官方文档和实际控制台，不在本地包中自动完成。

微信 web-view 官方入口：[组件文档](https://developers.weixin.qq.com/miniprogram/dev/component/web-view.html)。本次环境未能读取该官方页面正文，因此不能把本说明当作微信最新主体准入政策确认；正式发布前必须复核。

### 5.2 单独试运行示例

1. 微信开发者工具导入 `wechat-demo/`，不是网页源码目录或整个交付目录。
2. 在导入界面填写自己的组织小程序 AppID；`project.config.json` 中 AppID 刻意留空，不包含原站真实 AppID。
3. 修改 `config/map-config.js`：`MAP_ORIGIN` 是你的 HTTPS 域名，末尾不要加 `/`；默认值 `https://nkulawer.cn` 仅沿用原项目目标域名，不保证已上线。`MAP_PATH` 默认 `/campus-map/`。
4. 确认该域名已部署第 4 节网页并完成业务域名配置。
5. 编译，点击“打开校园地图”。首次示例不需要安装 npm 包，也不带资料库或其他业务。
6. 先开发者工具验证，再用有权限的体验版在微信 iOS／Android 真机测试。不要把“不校验合法域名”当作正式接入方案。

示例是普通 JavaScript，不需要 TS 编译插件。它不是原小程序的整站备份。未提供真实 AppID，因此本交付不声称已由开发者工具或真实微信账号完成编译、上传和审核。

### 5.3 合并到现有小程序（推荐实际接入方式）

先备份或建立版本控制分支，然后只按需复制这些新增文件，遇同名文件先比较，不直接覆盖：

```text
wechat-demo/pages/campus-map/index.js
wechat-demo/pages/campus-map/index.json
wechat-demo/pages/campus-map/index.wxml
wechat-demo/pages/campus-map/index.wxss
wechat-demo/utils/campus-map-links.js
wechat-demo/config/map-config.js
```

在原小程序 app.json 的 pages 数组追加 `"pages/campus-map/index"`，保留原有页面、tabBar、组件和 window 配置。不要用示例 app.json 替换原 app.json；如果原项目已有 TypeScript 的同名地图页，不要同时复制 index.js，选择保留已有 TS 页并对照配置。

原首页合适位置增加入口：

```xml
<navigator url="/pages/campus-map/index" hover-class="none">
  <view>校园地图</view>
</navigator>
```

如果想直接进入图书馆，使用 `/pages/campus-map/index?buildingId=osm-building-616829077`。示例页只接受白名单格式的地点 ID，不接受 onLoad 的任意外部 URL。返回兜底用 `/pages/home/index`，若你的首页路径不同，修改地图页 goBack 的兜底路径。不要改动课程页、资料页或其他已有 web-view。

小程序原生 web-view 不适合在其上叠加普通原生工具栏；本项目已把搜索、图层和地点详情做在 H5 网页内。无需再次在原生页画一套地图 UI。

### 5.4 分享与状态

网页选中地点后更新 URL 的 buildingId；全校复位会清除。原生分享优先使用微信回调提供的 webViewUrl 解析同源地点 ID，字段不可用时退回初始入口 ID，不能保证所有微信版本都能实时分享最后选择。示例不使用 postMessage 实时同步，也不包含定位权限或后台追踪。请用两个真机账号验收：选地点、分享、对方打开；复位后再次分享，检查不会残留旧地点。

收藏和最近只保存在网页 localStorage 中，可能随微信清理缓存而消失；不属于账号云端收藏。首次包下载／渲染耗时依设备和网络而变，不能把桌面模拟通过当作手机帧率承诺。

## 6. 模型、地图与后续修改

- 精细模型是 `campus-map/src/main.ts` 和各模型模块的程序化几何；基础轮廓来自 src/data，原始数据在 data。完整索引见 `models/模型与代码索引.md`。
- `models/model-catalog.json` 可用于对接 ID、坐标和轮廓，不包含全部精细网格／贴图。需要 GLB 导出或迁移引擎时是额外开发，不要直接拿轮廓 JSON 宣称精细模型已迁移。
- 地点显示名和别名改 `src/map-places.ts`，模糊搜索改 `src/map-search.ts`；不要为了改标签直接修改建筑生成数据。
- 绿地配色为 `#B8D0A0`，水体 `#ADCBD6`，树形／树位保持当前确认版。修改配色时需同步 2D、3D 的对应入口并运行 check。
- 不要执行 `npm run refresh:data`、`build:model` 重建最新 OSM 来“更新一下”：它们可能覆盖已手工补绘／命名的数据。只有明确开展数据迁移并备份时才使用。
- 保护校验在 reference/building-model-preservation.json；不要为了通过测试重写基线。print-theme-building-baseline 脚本依赖历史备份，只作维护参考，不是交付运行步骤。

## 8. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 手机访问不了局域网预览 | 手机用了 127.0.0.1、Wi-Fi 隔离、防火墙、服务已停、端口不符 |
| 上线白屏，JS 404 | 上传成 /campus-map/dist/、base 与路径不符、漏 assets、主站路由把 JS 返回成 HTML |
| 微信提示域名问题 | 业务域名未配置／未验证、URL 域名与控制台不一致、HTTPS 证书链异常 |
| 只出现 2D | ?mode=2d、WebGL2 不可用、GPU 资源不足或上下文丢失；先确认降级后仍能用 |
| 手机较卡 | 默认使用远近自动、省电档对比、关闭其他高负载网页；不要把完整精细设为全设备默认 |
| 地点图钉比名单少 | 标签正在避让／分类筛选，移动或拉近看；未知名称不会编造公开标签 |
| 新版本上传后旧用户打不开资源 | 清理了旧哈希 assets 或 HTML 缓存太久，检查共享资源保存策略 |
| 返回按钮兜底失败 | 修改示例 goBack 的首页路径，不能假定所有项目首页都叫 pages/home/index |
| PowerShell 不允许运行 npm.ps1 | 使用 `npm.cmd ci`、`npm.cmd run check`；不必全局放开执行策略 |

## 9. 更新和回滚

每次更新新建 release 目录，保存上一版本及资源。发布前先校验、测试，再由管理员切换 current。回滚时切回上一个地图 release，保留共享哈希资源，不修改主站文件、API 或数据库。小程序可暂时移除首页地图入口或回到此前版本，不删除课程／资料页。

改用其他域名或子路径，需要同步网页 base、服务器 location、config/map-config.js、业务域名及分享验证。不要把测试用的局域网 IP、个人证书或 AppID 固化进共享交付包。
