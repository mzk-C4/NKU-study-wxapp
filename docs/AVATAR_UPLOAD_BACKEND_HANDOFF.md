## 3. 现有资料接口必须明确的语义

```http
POST /api/v1/me/profile
Authorization: Bearer <现有会话 Token>
Content-Type: application/json
```

只更换头像的正文：

```json
{ "avatar_url": "https://resources.nkustudy.top/avatars/opaque-version-id.jpg" }
```

要求：

1. 省略 `nickname` 保留原昵称；省略 `avatar_url` 保留原头像。不能默认设为空字符串；无昵称的已有账号也必须可以单独改头像。
2. 从有效会话确定用户，不能通过正文 user_id/openid 指定其他账号。新上传资源必须属于当前用户且审核通过；只验证 HTTPS 不足以防止绕过审核或引用他人待绑定资源。
3. 保存失败不能清空旧头像/昵称；成功后 `GET /me` 与下一次 `/auth/wechat` 的 user 都返回新头像。
4. 成功响应沿用 `{ "code": 0, "data": { "user": { ... } } }`，返回完整最新 user，包括 id、nickname、avatar_url 及现有公开字段。不要返回只有 avatar_url 的局部 user。
5. 对同一头像 URL 的重复保存保持幂等。超时可能发生在已落库之后，客户端不会自动重发；用户可重进核对，再手动重试。
6. 旧头像仅在新头像成功绑定后按保留策略清理；上传成功但绑定失败/取消产生的孤立文件由服务器回收。不要先删旧头像。

资料保存响应示例（模拟值；保留后端已有的其他公开 user 字段）：

```json
{
  "code": 0,
  "data": {
    "user": {
      "id": 123,
      "nickname": "原昵称",
      "avatar_url": "https://resources.nkustudy.top/avatars/opaque-version-id.jpg",
      "has_web_password": false,
      "created_at": "2026-09-01T00:00:00.000Z",
      "last_login_at": "2026-09-28T00:00:00.000Z"
    }
  }
}
```

当前页面核对返回 user 的 id 与当前用户一致、avatar_url 与上传结果一致、nickname 与更换前一致。若需规范化头像地址，应在上传响应就返回最终地址；不同的绑定流程需一并回交，便于前端调整。`GET /me` 也读取 `data.user`；重新登录继续沿用既有 token/expires_in/user 响应结构，不新增登录协议。

## 4. 建议错误响应

沿用公开接口 `{ "code": "ERROR_CODE", "message": "受控说明" }`；以下错误码为前后端协商建议，并非生产已有声明。

| HTTP | code | 含义 |
|---|---|---|
| 400 | `AVATAR_INVALID_IMAGE` | 缺少文件、解码失败或不支持的格式 |
| 401 | `AUTH_REQUIRED` | 会话无效、过期或已撤销 |
| 403 | `AVATAR_CONTENT_REJECTED` | 图片未通过安全审核 |
| 403 | `AVATAR_NOT_OWNED` | 不能绑定不属于本人的上传资源 |
| 413 | `AVATAR_TOO_LARGE` | 字节数或解码尺寸超限 |
| 429 | `RATE_LIMITED` | 超出上传频率或配额 |
| 503 | `AVATAR_UPLOAD_UNAVAILABLE` | 上传、存储或审核服务暂不可用 |

普通网络/图片/存储失败不应撤销有效登录；仅真实认证失效走 401。公共错误不得包含存储密钥、内部路径、供应商堆栈或完整敏感链接。
