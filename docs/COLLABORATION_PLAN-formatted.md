## 一、项目目标

使用原生微信小程序完成 NKUStudy 移动端 MVP，覆盖首页、课程、搜索、资料、评价、指南和个人中心等 12 个设计界面，并实现：

- 游客直接浏览课程、资料、评价和指南；
- 收藏、投稿、写评价时再触发微信登录；
- 从 `NKUStudy.top` 的现有数据源读取真实内容；
- 资料投稿、课程评价、失效反馈进入审核流程；
- 完成接口联调、真机验收和微信体验版发布。

## 二、本次调整后的职责边界

### 2.1 五人技术组负责

- 小程序页面、公共组件、交互和异常状态；
- `/api/v1` 接口契约、字段映射与联调；
- GitHub Issues、PR、项目看板和代码审核；
- 微信公众平台配置、真机测试和体验版发布；
- 由沈弋皓汇总接口实现，并在其拥有的服务器上完成生产部署。

### 2.2 沈弋皓作为服务器所有者负责

- 生产服务器账号、SSH、Caddy、进程和防火墙管理；
- 部署或反向代理 `https://nkustudy.top/api/v1`；
- 配置微信服务端密钥、运行环境变量和备份；
- 轮换交接材料中已经暴露的服务器、管理端和对象存储凭据；
- 向其他成员提供非敏感的 API 地址、健康检查和部署结果。

### 2.3 明确不做的事情

- 马兆坤不登录或管理不属于自己的服务器，也不负责创建部署账号；
- 五人组不在群聊、飞书或 GitHub 中传递生产密码、Token、Secret；
- 小程序不调用网站的 `/admin-api/*`，不接触管理端 Cookie；
- 小程序不保存对象存储管理密钥，不通过客户端拼接私有地址；
- 不把小程序仓库中的参考 `server/` 直接部署成第二套生产数据源。

## 三、生产架构与数据原则

1. `NKUStudy.top` 现有课程 JSON 和资源对象存储是生产数据的唯一权威来源。
2. 小程序仓库中的 `server/` 仅用于接口契约、模拟数据和本地联调。
3. 沈弋皓负责把现有网站数据映射为统一的 `Course`、`CourseOffering`、`Resource`、`Review`、`Guide` 类型。
4. 沈弋皓负责把该适配层部署到生产环境，并通过 HTTPS 暴露 `/api/v1`。
5. 资料下载直接使用公开、受控的资源域名；写入操作统一提交到专用 API 并进入审核。

## 八、GitHub 与飞书协作规则

- `main` 开启分支保护，禁止直接推送。
- 每项任务建立 GitHub Issue，填写负责人、截止日期、验收条件和关联 PR。
- 每个 PR 至少一名非作者审核；接口变更由沈弋皓审核，最终合并由马兆坤确认。
- 使用 Squash Merge；单个 PR 只处理一个任务或一个页面模块。
- Commit 前缀统一为 `feat:`、`fix:`、`docs:`、`refactor:`、`chore:`。
- 小程序仓库只记录 API 契约；生产部署变更在网站仓库完成，并通过 Issue 或 PR 互相链接。
- 项目看板若保持私有，必须邀请沈弋皓、邵游堃、洪修睿和丁宇鑫。

## 九、安全规则

- 交接文件中含敏感信息的版本不得上传 GitHub、飞书或群聊。
- 已经在聊天或交接文件中出现的凭据一律按泄露处理，由沈弋皓轮换。
- `.env`、小程序 AppSecret、SSH 私钥、对象存储密钥和管理端密码不得提交仓库。
- 小程序只使用 HTTPS API 域名，禁止硬编码服务器 IP。
- 日志不得记录 OpenID、Token、完整投稿链接或其他可复用凭据。
- 五人组只索取完成联调所需的非敏感信息，不索取 root 密码或生产密钥。
