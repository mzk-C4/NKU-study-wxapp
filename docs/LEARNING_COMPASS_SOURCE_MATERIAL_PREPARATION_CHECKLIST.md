## 六、Markdown电子化规范

电子化阶段只忠实转写，不摘要、不归类、不改写规则。

每份Markdown开头记录最小信息：

```markdown
# 文件原始标题

> 来源主体：
> 文号：
> 发布日期：
> 生效日期：未注明/原文日期
> 适用范围：按原文填写，未注明则写“未注明”
> 原始文件：相对路径或文件名
> 官方链接：
> 电子化说明：由PDF/DOCX/网页整理；是否人工核验
```

正文要求：

- 保留原始章、节、条和项目编号；
- 表格使用Markdown表格，过宽表格可分段但不能改变对应关系；
- 保留文号、日期、数字、否定词和例外条件；
- PDF按需要加入 `[原PDF第 001 页]` 等页码锚点；
- 网页保留正文标题、发布日期和附件名称/链接；
- DOCX中的批注、修订痕迹和个人信息不直接进入正文；
- XLS/XLSX按工作表分别转为Markdown表格，保留工作表名；
- 看不清或无法确认的位置写 `[待核验：……]`，不能猜；
- 原文疑似错误也照录，并另加“电子化核验备注”，不能静默改正；
- 不在这一阶段添加一级分类、标签、AI摘要或产品解释。

## 七、SOURCE_MANIFEST最小字段

每份材料只需要登记：

| 字段 | 含义 |
|---|---|
| `source_id` | `SRC-001`等稳定编号 |
| `title` | 原始标题 |
| `issuer` | 发布主体 |
| `document_no` | 文号，没有则留空 |
| `published_at` | 发布日期，没有则标未注明 |
| `scope` | 原文明示的适用范围 |
| `original_path` | 本地原始文件路径 |
| `markdown_path` | 对应Markdown路径 |
| `official_url` | 官方页面或原文件链接 |
| `conversion_status` | `ready / needs-conversion / needs-review` |
| `notes` | 版本差异、附件或待核验问题 |

不需要在这个阶段维护关键词、分类、AI向量、复杂有效期或知识条目ID。
